# v0.1.152 上游融合设计

- 日期：2026-07-13
- 执行者：Devil
- 上游标签：`v0.1.152` (`b73d8c3ef`)
- 本地基线：`ffb1475df65b`

## 目标

完整吸收上游 v0.1.152 相对 v0.1.151 的有效功能与缺陷修复，同时保留本地随机快速验证题、NewApi 工具、Ops 观测、版本展示和既有网关增强。

## 融合策略

在独立 worktree 和 `codex/merge-v0.1.152` 分支工作。以上游 `v0.1.151..v0.1.152` 的净变更为输入，按功能组融合，不直接覆盖本地文件，也不把原工作树未提交内容带入分支。

冲突处理以行为为单位：先确认上游测试表达的预期，再保留本地额外能力并接入上游修复。生成的 Ent 文件与 migration 必须作为同一 schema 变更整体吸收。

## 功能范围

1. Codex Responses/Chat/Anthropic custom 工具、`tool_search` 和 namespace 子工具桥接。
2. compact keepalive writer 生命周期、body signal、remote compaction 与续链 item ID 修复。
3. Fast/Flex 用户级策略的管理端搜索选择能力。
4. Codex alpha/search 独立端点转发、分组按次价格和计费链路。
5. Grok OAuth、API Key、OpenCode adapter、prompt cache、配额显示与调度诊断修复。
6. `opsCaptureWriter` nil 访问、cache creation token、WebSocket 兼容等随版本修复。
7. 主版本更新为 `v0.1.152`，镜像小版本仍由后续发布流程单独确定。

## 保留边界

- 所有通用探测继续使用本地随机快速验证题，不恢复上游固定提示词。
- `VersionBadge` 继续由 `/admin/system/version.current_version` 提供主版本，并只保留一个 `v` 前缀。
- NewApi 签到、Token 成本工具和本地 Ops 页面保持现状。
- 本轮不构建镜像、不部署、不推送远端。

## 验证

按功能组运行上游新增聚焦测试；融合后运行相关 Go package、前端 Vitest、TypeScript typecheck、`gofmt`、`git diff --check` 和 server 编译切片。若项目全量测试存在既有失败，必须记录具体测试名并以基线对照，不把失败描述为通过。
