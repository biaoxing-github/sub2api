## 详细更新日志

1. `backend/internal/service/newapi_checkin_service.go` 按规范化 `base_url` 将签到平台与主平台 `openai/apikey` 账号关联，兼容末尾 `/` 和 `/v1` 差异，并在签到 Key 摘要中返回已引用账号及可关联账号。
2. `backend/internal/handler/admin/newapi_checkin_handler.go` 与 `backend/internal/server/routes/admin.go` 增加 Key 关联写入接口，支持将签到工具中的生成 Key 追加或替换到指定主平台账号。
3. 追加模式复用主平台既有 Key 合并与去重语义；替换模式仅保留目标 Key，并同步清理不再存在 Key 的禁用状态。
4. `frontend/public/newapi-checkin/index.html` 与 `frontend/src/views/admin/tools/newapiCheckinLegacy.generated.ts` 在平台目录中高亮已被主平台引用的 Key，展示引用账号标识，并提供带确认提示的追加/替换操作。
5. 后端 service、handler、routes 与前端 Vitest 增加 URL 归一化、引用识别、请求载荷和交互行为覆盖；本轮没有数据库 schema 或数据迁移。

## 用户可见行为

- 管理员在“工具箱 -> NewApi 签到 -> 平台目录”中可以直接识别哪些生成 Key 已被主 Sub2API 平台账号引用。
- 已引用 Key 使用高亮样式并显示对应主账号名称；同一站点的可关联账号按 `base_url` 自动匹配。
- 管理员可以选择目标账号，将签到 Key 追加到现有 Key 列表，或确认后替换该账号的全部 Key。
- 页面操作前会明确展示目标账号和追加/替换影响；本次发布未对生产账号执行真实追加或替换。
