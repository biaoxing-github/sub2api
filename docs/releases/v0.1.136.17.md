## Detailed Changelog

Compared with `v0.1.136.16`, this release changes the OpenAI `/responses` scheduler-exhaustion stream behavior.

1. Bound client-facing scheduler wait
   - Module: `backend/internal/handler/openai_gateway_handler.go`
   - Change: added `openAISchedulerExhaustionClientWaitMax = 90 * time.Second`.
   - User-visible impact: in infinite scheduler-probe mode, the gateway no longer keeps a client-visible stream waiting forever when no OpenAI account is available.

2. Use protocol-neutral pending keepalive
   - Module: `backend/internal/handler/openai_gateway_handler.go`
   - Change: scheduler pending markers are written as SSE comments, for example `: scheduler_probe_pending`, instead of fake OpenAI Responses `data:` events.
   - User-visible impact: Codex Desktop receives keepalive bytes without seeing an invalid Responses event.

3. Emit protocol-valid failure after the wait cap
   - Module: `backend/internal/handler/openai_gateway_handler.go`
   - Change: after the scheduler wait deadline is exceeded, the handler writes a Responses-compatible `response.failed` through the existing streaming-aware error path.
   - User-visible impact: if the account pool does not recover, the client gets an explicit upstream-capacity failure instead of a silent stream.

4. Cover the behavior with tests
   - Module: `backend/internal/handler/openai_gateway_handler_test.go`
   - Change: added tests for SSE-comment pending frames and the 90-second scheduler client wait deadline.
   - User-visible impact: future changes are less likely to reintroduce fake `data:` pending events or unbounded client waits.
