## Detailed Changelog

Compared with `v0.1.136.20`, this release absorbs the first-phase stability improvements selected from sub2api 137/138/139 and juhe-ai feature/20250617, focused on low-risk runtime reliability and scheduler maintenance.

1. Add zstd upstream response decompression
   - Modules: `backend/internal/repository/http_upstream.go`, `backend/internal/repository/decompress_response_test.go`
   - Change: upstream responses with `Content-Encoding: zstd` are now decompressed before downstream handling; invalid zstd keeps the original body and records `zstd_decompress_failed`.
   - User-visible impact: compressed upstream replies no longer leak through as unreadable bytes or false negatives.

2. Treat bad 2xx bodies as failover candidates
   - Modules: `backend/internal/service/openai_gateway_service.go`, `backend/internal/service/openai_gateway_service_test.go`
   - Change: empty body, HTML body, and other non-protocol 2xx responses now trigger account failover instead of being treated as ordinary success.
   - User-visible impact: upstream edge pages and malformed success replies no longer look like healthy model output.

3. Preserve SSE event:error semantics and ops diagnostics
   - Modules: `backend/internal/service/openai_gateway_service.go`, `backend/internal/service/openai_gateway_service_test.go`
   - Change: streaming `event:error` now keeps the real upstream error message in client-visible failure output and in ops diagnostics.
   - User-visible impact: interrupted Responses streams surface a more truthful error instead of a generic missing-terminal failure.

4. Deduplicate repeated function-call arguments before client write
   - Modules: `backend/internal/service/openai_gateway_service.go`, `backend/internal/service/openai_gateway_service_test.go`
   - Change: normal streaming and passthrough streaming now normalize repeated Responses function-call `arguments` before writing to the client.
   - User-visible impact: Codex clients stop receiving duplicated JSON arguments in streamed tool calls.

5. Improve image response failover handling
   - Modules: `backend/internal/service/openai_images_responses.go`, `backend/internal/service/openai_images_test.go`
   - Change: adds handling for `response.incomplete`, content-filter/moderation client errors, missing image output, and OAuth image 5xx bodies.
   - User-visible impact: image-generation failures are classified more accurately and can fail over or surface better errors.

6. Tighten provider compatibility and token refresh behavior
   - Modules: `backend/internal/pkg/apicompat/anthropic_to_responses.go`, `backend/internal/service/gemini_messages_compat_service.go`, `backend/internal/service/vertex_service_account.go`, `backend/internal/service/token_refresh_service.go`
   - Change: adds Anthropic reasoning-effort compatibility, Vertex beta filtering, Gemini AI Studio schema cleanup, and token-refresh non-retryable/redaction handling.
   - User-visible impact: provider-specific payloads stop failing on known unsupported shapes and token-refresh errors leak less sensitive detail.

7. Add scheduler outbox deduplication and cleanup
   - Modules: `backend/internal/repository/scheduler_outbox_repo.go`, `backend/internal/service/scheduler_outbox.go`, `backend/internal/service/scheduler_snapshot_service.go`, `backend/migrations/161_scheduler_outbox_dedup_key.sql`, `backend/migrations/162_scheduler_outbox_pending_dedup_key_index_notx.sql`
   - Change: scheduler outbox now persists `dedup_key` for idempotent events, releases the key when polled, and cleans consumed rows after watermark commit under an advisory lock.
   - User-visible impact: repeated group/account rebuild events are less likely to pile up or retrigger redundant work.

```nginx
upstream sub2api_active {
  server sub2api-blue:8080;
  keepalive 32;
}
```

Then run:

```powershell
docker exec sub2api-proxy nginx -t
docker exec sub2api-proxy nginx -s reload
```
