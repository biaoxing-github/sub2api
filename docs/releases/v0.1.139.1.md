## Detailed Changelog

Compared with `v0.1.136.21`, this release ships the Phase 2 Codex-focused enhancements selected from the sub2api `v0.1.137` to `v0.1.139` review. Global whitelist/blacklist and PAT auth were intentionally skipped because this local sub2api deployment does not need those admission controls.

1. Extend `codex_cli_only` enforcement to Chat Completions
   - Modules: `backend/internal/service/openai_gateway_chat_completions.go`, `backend/internal/service/openai_gateway_service.go`, `backend/internal/service/openai_gateway_service_codex_cli_only_test.go`
   - Change: OpenAI OAuth accounts with `codex_cli_only` now reuse the existing official Codex client detector on `/v1/chat/completions`; API Key raw chat completions remain unaffected.
   - User-visible impact: OAuth accounts configured for Codex-only use reject non-official clients consistently across Responses and Chat Completions paths.

2. Add Codex rejection fingerprint diagnostics
   - Modules: `backend/internal/service/openai_gateway_service.go`, `backend/internal/service/openai_gateway_service_codex_cli_only_test.go`
   - Change: rejected Codex-only requests now log `codex_fingerprint_profile` plus hashed body/header fingerprints for sensitive request identity fields.
   - User-visible impact: operators can identify why a client was rejected without logging raw session, thread, or installation identifiers.

3. Adopt GPT-5.5 Codex base instructions
   - Modules: `backend/internal/pkg/openai/constants.go`, `backend/internal/pkg/openai/constants_test.go`, `backend/internal/pkg/openai/instructions_gpt5_5.txt`
   - Change: `gpt-5.5` uses the absorbed GPT-5.5 Codex prompt; `gpt-5.4`, bare `gpt-5`, and unknown GPT-5-family values now fall back to that latest prompt.
   - User-visible impact: generated Codex configuration tracks the newer upstream instruction set instead of the older GPT-5.1/GPT-5.4 prompt.

4. Refresh generated Codex and Claude Code templates
   - Modules: `frontend/src/components/keys/UseKeyModal.vue`, `frontend/src/components/keys/__tests__/UseKeyModal.spec.ts`, `frontend/src/utils/ccswitchImport.ts`, `frontend/src/utils/__tests__/ccswitchImport.spec.ts`
   - Change: generated Codex config, WebSocket config, and CC Switch OpenAI imports default to `gpt-5.5`; Codex config enables `[features] goals = true`; Claude Code terminal templates set `CLAUDE_CODE_ATTRIBUTION_HEADER=0`.
   - User-visible impact: copied client snippets default to the new model line and suppress Claude Code attribution header behavior where the template is used.

5. Bump the visible major version line
   - Modules: `backend/cmd/server/VERSION`
   - Change: the server version line is now `v0.1.139`, and the immutable image version is `v0.1.139.1`.
   - User-visible impact: binary version output reports `Sub2API v0.1.139 (image: v0.1.139.1, commit: 16caf15094b5, built: 2026-06-30T06:26:33Z)`.

If the new blue active container shows health-check failures, panic/fatal logs, migration errors, bind/listen errors, or widespread gateway failures, switch the proxy back to green:

```nginx
upstream sub2api_active {
  server sub2api-green:8080;
  keepalive 32;
}
```

Then run:

```powershell
docker exec sub2api-proxy nginx -t
docker exec sub2api-proxy nginx -s reload
```
