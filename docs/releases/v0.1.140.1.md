## Detailed Changelog

Compared with `v0.1.139.1`, this release ships the selected cache-hit, stability, performance, and v0.1.140 absorption slices. It does not merge unrelated upstream payment/frontend/product changes.

1. Improve upstream prompt/request cache friendliness
   - Modules: `backend/internal/service/openai_compat_prompt_cache_key.go`, `backend/internal/service/openai_gateway_chat_completions.go`, `backend/internal/service/openai_gateway_messages.go`
   - Change: Chat compat `prompt_cache_key` seed now includes developer instructions; Chat prompt-cache session IDs are isolated by API key; Chat and Messages upstream JSON uses stable no-HTML-escape marshaling.
   - User-visible impact: compatible Codex/Anthropic bridge requests keep more stable upstream bodies and reduce avoidable session/key collisions.

2. Move wait queue accounting off the immediate hot path
   - Modules: `backend/internal/handler/gateway_helper.go` and gateway handler callers.
   - Change: immediate user-slot acquisition no longer writes Redis wait counters; only real waits increment and release counters.
   - User-visible impact: normal non-waiting requests do less coordination work before reaching upstream.

3. Absorb v0.1.140 image/Codex stability fixes
   - Modules: `backend/internal/service/image_output_accounting.go`, `image_generation_intent.go`, `openai_codex_transform.go`, `openai_gateway_service.go`, `openai_ws_forwarder.go`
   - Change: image output counting avoids text-only false positives; raw-body image billing preserves tool image model without full JSON decode; Codex image bridge sets `tool_choice=auto` for HTTP and WS paths while preserving explicit choices.
   - User-visible impact: image requests are billed against the correct image model and Codex image bridge requests are shaped closer to upstream expectations.

4. Avoid useless account failover on context-window errors
   - Modules: `backend/internal/service/openai_stream_policy.go`, `openai_gateway_chat_completions.go`, `openai_gateway_service.go`, `openai_account_runtime_block_fastpath.go`
   - Change: OpenAI context-window/context-length/token-limit style failures pass through instead of marking accounts/path as failed.
   - User-visible impact: oversized requests surface the real model/context error and do not waste healthy accounts.

5. Reduce fallback pricing log noise and extend GLM fallback
   - Modules: `backend/internal/service/billing_service.go`
   - Change: fallback pricing warnings are deduplicated by model and GLM-5/GLM-4.6/GLM-5.2 fallback coverage is extended.
   - User-visible impact: operator logs are quieter while billing fallback remains explicit.

6. Converge manual blue-green release automation
   - Module: `deploy/release-bluegreen.ps1`
   - Change: the release script defaults to dry-run, separates candidate deployment from cutover, builds from committed HEAD, avoids PowerShell 5 native stderr traps, and uses a temp build context instead of binary tar piping.
   - User-visible impact: release execution is still manual/gated, but repeatable and less error-prone on Windows.

7. Bump the visible major version line
   - Module: `backend/cmd/server/VERSION`
   - Change: server version is now `v0.1.140`; immutable image version is `v0.1.140.1`.
   - User-visible impact: deployed binary reports `Sub2API v0.1.140 (image: v0.1.140.1, commit: 2b37b941016c, built: 2026-07-01T05:25:46Z)`.

## Rollback

If the new green active container shows health-check failures, panic/fatal logs, migration errors, bind/listen errors, or widespread gateway failures, switch the proxy back to blue:

```nginx
upstream sub2api_active {
  server sub2api-blue:8080;
  keepalive 32;
}
```

Then run:

```powershell
docker exec sub2api-proxy nginx -t
docker exec sub2api-proxy nginx -s reload
```

Rollback image: `sub2api:v0.1.139.1` on `sub2api-blue`.
