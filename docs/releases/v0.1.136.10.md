## 详细更新日志

相较 `v0.1.136.9`，本版本继续收口 free-rawchat / `https://new.sharedchat.cc/codex` 的 `codex_access_restricted` 问题，补齐真实上游最终接受的 Codex API Key 模拟请求形态。

1. API Key Codex 模拟生成稳定 installation_id
   - 涉及模块：`backend/internal/service/openai_codex_transform.go`。
   - 变更内容：新增 `applyCodexCLISimulationClientMetadata`、`resolveCodexSimulationInstallationID` 和相关 helper。OAuth 账号继续复用真实 `device_id`；API Key 账号按 `account_id + normalized base_url` 派生稳定 UUID，本轮账号 470 / `https://new.sharedchat.cc/codex` 的派生值为 `81b4ba42-4573-4eff-943c-4c57c5d55b9a`。
   - 用户可见影响：同一 API Key Codex 模拟账号不再每次请求都像新安装客户端，`client_metadata`、`x-codex-turn-metadata` 与请求头里的 installation_id 保持一致。

2. API Key Codex 模拟强制补齐真实 Codex 版本头
   - 涉及模块：`backend/internal/service/openai_gateway_service.go`。
   - 变更内容：账号级 Codex 模拟路径现在会显式写入 `OpenAI-Beta: responses=experimental`、`Version: 0.141.0` 和 `x-codex-installation-id`；`ensureOpenAICodexClientMetadataHeaders` 会优先复用请求体里的 `session_id`、`thread_id`、`window_id`、`installation_id` 和 `x-codex-turn-metadata`，缺失时再补齐。
   - 用户可见影响：`free-rawchat` 这类 API Key Codex 模拟账号发往上游时，头部和请求体中的 Codex 身份字段不再割裂，降低被 `new.sharedchat.cc/codex` 判定为非官方 Codex 客户端的概率。

3. 网关正式转发前补齐 body 级 client_metadata
   - 涉及模块：`backend/internal/service/openai_gateway_service.go`、`backend/internal/service/account_test_service.go`、`backend/internal/service/account_usage_service.go`、`backend/internal/service/account_probe.go`。
   - 变更内容：在 API Key Codex 模拟且非 passthrough、非 compact 的 `/responses` 路径，网关会在转发前直接补全请求体 `client_metadata`；管理端账号测试、账号体检和使用量探测也统一复用同一套 metadata 生成逻辑。
   - 用户可见影响：管理端体检、管理端测试和真实网关请求对同一账号的 Codex 模拟行为保持一致，不再出现“体检可以、真实请求不行”或“真实请求可以、管理端测试不行”的请求形态分叉。

4. 回归测试与真实 upstream 验证
   - 涉及模块：`backend/internal/service/openai_codex_transform_test.go`、`backend/internal/service/openai_gateway_service_codex_cli_only_test.go`、`backend/internal/service/account_test_service_openai_test.go`、`backend/internal/service/openai_oauth_passthrough_test.go`。
   - 变更内容：新增并扩展 installation_id、Version/OpenAI-Beta、body/header turn metadata 一致性的回归断言；同时保留 `Accept: text/event-stream` 覆盖验证。
   - 用户可见影响：后续如果再次出现 Codex 模拟头、体 metadata 或 installation_id 对不齐，聚焦单测会直接失败。

## 回滚方式

如出现健康检查失败、panic/fatal、迁移错误、端口绑定失败或网关请求大面积失败，立即将 `D:\sub2api-deploy\proxy\upstreams\active.conf` 改回：

```nginx
upstream sub2api_active {
  server sub2api-blue:8080;
  keepalive 32;
}
```

然后执行：

```powershell
docker exec sub2api-proxy nginx -t
docker exec sub2api-proxy nginx -s reload
```
