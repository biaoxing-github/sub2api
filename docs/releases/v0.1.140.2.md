## Detailed Changelog

Compared with `v0.1.140.1`, this release fixes a compatibility bug in upstream health checks for OpenAI-compatible providers such as zz1cc.

1. Remove unsupported `max_output_tokens` from account health-check payloads
   - Modules: `backend/internal/service/account_probe.go`, `backend/internal/service/account_probe_test.go`
   - Change: `buildOpenAIResponsesProbePayload` no longer sends `max_output_tokens` in internally generated Responses probe bodies.
   - User-visible impact: upstream account health checks no longer fail only because a compatible provider rejects the optional `max_output_tokens` parameter.

2. Keep API Key probe payloads consistent with account probe payloads
   - Modules: `backend/internal/service/api_key_probe.go`, `backend/internal/service/api_key_probe_test.go`
   - Change: user API Key probe runner now also uses the no-`max_output_tokens` Responses payload.
   - User-visible impact: manual API Key probe and account probe behavior stay aligned for the same provider compatibility rule.

3. Preserve the useful Responses probe shape
   - Modules: `backend/internal/service/account_probe.go`
   - Change: the probe still sends `model`, list-shaped `input`, `stream`, `store=false`, and `instructions`.
   - User-visible impact: providers that require list-shaped `input` and instructions keep working while unsupported output-token parameter errors are avoided.
