## Detailed Changelog

Compared with `v0.1.136.15`, this release ships per-key failure visibility for multi-key OpenAI API-key accounts during account manual probes and scheduling-pool manual probes.

1. Keep selected-key failures on the matching key record
   - Modules: `backend/internal/service/ratelimit_service.go`, `backend/internal/service/account.go`
   - Change: 429 and OpenAI 403 insufficient-balance errors now keep the failure scoped to `api_keys_disabled` for the selected key, even when it is the last active key.
   - User-visible impact: the whole account is not frozen just because one key failed; the administrator can see which key entered cooldown.

2. Persist upstream error text on disabled key records
   - Modules: `backend/internal/service/account.go`, `backend/internal/handler/dto/types.go`, `backend/internal/handler/dto/mappers.go`
   - Change: `api_keys_disabled` details now carry `last_error`, and account DTO `api_key_items` exposes the field.
   - User-visible impact: the failed key row can show the upstream error, cooldown reason, disabled-until time, and disable count.

3. Return sanitized account DTOs from manual account probes
   - Modules: `backend/internal/handler/admin/account_handler.go`, `backend/internal/handler/admin/account_handler_test.go`
   - Change: `/admin/accounts/:id/manual-probe` returns the sanitized DTO account with `api_key_items` instead of raw credentials.
   - User-visible impact: the frontend can refresh the tested account and show per-key cooldown/error state without exposing plaintext keys.

4. Refresh account and scheduling-pool UI after manual probes
   - Modules: `frontend/src/components/account/AccountAPIKeyCredentialsFields.vue`, `frontend/src/components/admin/account/AccountTestModal.vue`, `frontend/src/views/admin/AccountsView.vue`, `frontend/src/views/admin/AccountSchedulingPoolView.vue`, `frontend/src/types/index.ts`
   - Change: account manual tests emit a refresh event; scheduling-pool manual probes refresh the pool after both success and failure responses while preserving the probe message.
   - User-visible impact: after either manual test path, the corresponding key row shows `reason`, `last_error`, `disabled_until`, and `disabled_count`, so bad keys can be identified and removed.
