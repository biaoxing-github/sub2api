## 详细更新日志

相较 `v0.1.136.15`，本版本修复 OpenAI 多 Key API Key 账号在人工测试连接和调度池测试连接中的 key 级错误可见性问题，并同步修正最后一个活跃 key 失败时被回退成账号级冻结的问题。

1. 多 Key 失败保持在对应 Key 的冷却记录上
   - 涉及模块：`backend/internal/service/ratelimit_service.go`、`backend/internal/service/account.go`
   - 变更内容：selected-key cooldown 不再因为当前 key 是最后一个活跃 key 就撤销冷却并回退为账号级临时不可调度；429 与 OpenAI 403 insufficient balance 都会保留到 `api_keys_disabled`。
   - 用户可见影响：多 Key 账号某个 key 失败后，账号不会被整体冻结，管理员能看到具体哪个 key 进入冷却。

2. 冷却 Key 保存上游错误详情
   - 涉及模块：`backend/internal/service/account.go`、`backend/internal/handler/dto/types.go`、`backend/internal/handler/dto/mappers.go`
   - 变更内容：`api_keys_disabled` 记录新增 `last_error`，DTO 的 `api_key_items` 同步透出该字段。
   - 用户可见影响：账号详情中的 key 行会显示上游返回的错误文本，例如 `API returned 401: invalid key`，方便定位不可用 key。

3. 账号人工测试返回脱敏 DTO 账号
   - 涉及模块：`backend/internal/handler/admin/account_handler.go`、`backend/internal/handler/admin/account_handler_test.go`
   - 变更内容：`/admin/accounts/:id/manual-probe` JSON 响应里的 `account` 改为 DTO，包含 `api_key_items`，并继续移除原始 `credentials.api_keys`。
   - 用户可见影响：人工测试连接结束后，前端可以拿到每个 key 的冷却和报错状态，同时不会泄露明文 key。

4. 前端测试后刷新并展示对应 Key 的错误
   - 涉及模块：`frontend/src/components/account/AccountAPIKeyCredentialsFields.vue`、`frontend/src/components/admin/account/AccountTestModal.vue`、`frontend/src/views/admin/AccountsView.vue`、`frontend/src/views/admin/AccountSchedulingPoolView.vue`、`frontend/src/types/index.ts`
   - 变更内容：账号测试弹窗完成后触发列表页刷新当前账号；调度池 manual probe 收到失败响应后也刷新池子并保留本次失败提示；key 状态行显示 `reason`、`last_error`、`disabled_until`、`disabled_count`。
   - 用户可见影响：管理员在账号人工测试连接和调度池测试连接后，可以直接在对应 key 行看到报错和冷却，到期前可据此删除坏 key。

## 回滚方式

如果切流后出现健康检查失败、panic/fatal、迁移错误、端口绑定失败、网关请求大面积失败，立即把 `D:\sub2api-deploy\proxy\upstreams\active.conf` 改回：

```nginx
upstream sub2api_active {
  server sub2api-green:8080;
  keepalive 32;
}
```

然后执行：

```powershell
docker exec sub2api-proxy nginx -t
docker exec sub2api-proxy nginx -s reload
```
