## 更新内容

- 账号级 OpenAI APIKey Codex CLI 模拟继续对齐真实 Codex `/codex/responses` 路径、Codex Desktop 0.138.0 请求头和 Responses body 形态。
- 收窄账号级模拟的传输层行为：不再默认套用内置 `Built-in Default (Node.js 24.x)` TLS 指纹，避免把真实 Codex CLI 请求伪装成 Node.js 24.x / Claude Code 传输。
- 全局 `codex_direct` 仍保留原有 TLS 指纹模板能力，继续通过 `gateway.openai_codex_direct_tls_fingerprint_profile_id` 控制。
- 管理端人工测试与正式网关热路径保持一致：free5 这类账号级模拟在人工测试中同样只改 URL、headers 和 body，不默认使用 Node.js 24.x TLS profile。

## 根因

- 真实 `@openai/codex@0.138.0 exec` 直连 free5 上游可以返回 `OK`。
- sub2api 候选在应用层已对齐真实 Codex 请求的 URL、headers 和 body，但 HTTPS 上游仍返回 `codex_access_restricted`。
- 进一步定位到账号级 Codex 模拟会默认进入 `Built-in Default (Node.js 24.x)` uTLS profile，并强制 OpenAI profile 走 HTTP/1.1；该传输指纹与真实 Codex CLI 不一致。
